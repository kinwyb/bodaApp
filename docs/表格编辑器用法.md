# 表格编辑器用法（antd 编辑器）

> 代码路径：`src/components/grid-table/editors/`
> 基准版本：`main`（2026-10-09，编辑器统一「本行访问」API 落地后）
> 说明：本文只讲怎么**用**，不做实现分析。要改实现看 `antd-editors.tsx` 的注释。

---

## 一、一句话结论

可编辑表格的编辑器**只有三步**：

```tsx
// 1. 注册一个具名编辑器（模块级执行一次即可）
registerAntdNumberEditor('preorder-size', { min: 0, precision: 0 }, {
    validator: (value) => (Number(value) > 999 ? '数量过大' : undefined),
});

// 2. 用名字挂到表格列的 editableFields 上
<GridTable editableFields={{ Number: 'preorder-size' }} onCellValueChange={handleChange} />

// 3. 页面接住编辑结果（必须接，见「六、必须遵守」）
const handleChange = useCallback(({ field, record, value }: GridTableCellValueChangeInfo) => {
    const key = String(record?.YupaiOrderID ?? '');
    setRows((rows) => rows.map((row) => (String(row.YupaiOrderID) === key ? { ...row, [field]: value } : row)));
}, []);
```

需要「选中一行，把它其他字段也填进本行」时，再加 `EditorOptions` 的钩子 —— 与控件类型无关，
Input / InputNumber / Select / DatePicker 用法完全一致（见「五、改本行其他字段」）。

> 只是「能改一下」的普通列，第 1 步可以省掉：`editableFields={{ Qty: true }}` 会按列类型
> 自动挑默认编辑器（见「三、注册 API」→「不写名字：`true` / `'auto'`」）。

## 二、文件结构

| 文件 | 职责 |
|---|---|

## 三、注册 API

```ts
registerAntdInputEditor(name?: string, props?: InputProps, options?: EditorOptions<string>): void
registerAntdNumberEditor(name?: string, props?: InputNumberProps, options?: EditorOptions<number | null>): void
registerAntdSelectEditor(name?: string, props?: SelectProps, options?: EditorOptions<unknown>): void
registerAntdDatePickerEditor(name?: string, props?: DatePickerProps, options?: EditorOptions<string>): void
registerAntdEditors(): void   // 一次注册四个基础编辑器（不带任何约束）
```

| 参数 | 说明 |
|---|---|
| `name` | 编辑器名。不传用默认名（`antd-input` / `antd-number` / `antd-select` / `antd-date`）。**同名幂等、先注册者生效**。 |
| `props` | 透传给 antd 控件。Select 必须给 `options`，否则是空下拉。 |
| `options` | 校验与行操作钩子，见「四」「五」。不传即「纯控件」。 |

### 具名 vs 默认名

**只要这个字段有校验、有联动、或需要特定 props，就必须另起一个具名实例**：

```ts
registerAntdInputEditor('preorder-detail-StyleCode', {}, { validator: (v) => rule(v) });
```

原因：注册表是**全局的**，同名的第二次注册会被静默忽略。复用 `ANTD_INPUT_EDITOR` 会让带校验的那次注册失效，
而失败方式是完全无声的（不报错、不生效）。

⚠️ **别做成「公共名的编辑器 + 带校验的字段另注册一个」两套，再用 `带校验的 ?? 公共的` 兜底** ——
取名字那一步等于把「控件类型」又判定了一遍，两处一旦对不上就是无声的错。V0280 踩过：
后道主工序要的是 Select，但它同时是单字段校验里的字段，名字被「带校验的 Input」顶掉，
实际编辑时是输入框，而那个 Select 注册成了**永远没人引用的死代码**（看代码还在，就是不生效）。

现在的做法是**每个字段各注册一个具名编辑器**（`preorder-detail-<字段>`）：
控件类型由列定义唯一决定，校验只是往同一个实例上挂 `validator`
（见 `yupaiOrderEditColumns.ts` 的 `registerDetailEditor`）。名字里带字段名也是必须的 ——
注册表同名先注册者生效，每个字段各占一个名字才不会发生看不见的覆盖。

### 不写名字：`true` / `'auto'`（自动编辑器）

只是「能改一下」的普通列，不用注册、也不用记名字，直接在 `editableFields` 里写 `true`
（写 `'auto'` 等价）—— 表格按列的 `dataType` 挑默认编辑器，并在第一次用到时自动注册好
四个公共编辑器（`resolveAutoEditor`，见 `editors/register.ts`）：

```tsx
<GridTable
    columns={COLUMNS}                                    // { field: 'Qty', title: '数量', dataType: 'int' }
    editableFields={{ Qty: true, YPDate: 'auto', Memo: true }}
/>
```

| 列的类型 | 自动用的编辑器 |
|---|---|
| `int` / `double` | `ANTD_NUMBER_EDITOR`（数字框，无步进按钮） |
| `date` / `datetime` | `ANTD_DATE_EDITOR`（日期选择器，值是字符串） |
| `text` / `tag` / 原生列 | `ANTD_INPUT_EDITOR`（输入框） |
| `boolean` | **不用编辑器** —— 它本身就是原生勾选框：写进 `editableFields` 就变可点，**单击直接切换 1 / 0**（见下） |

`tag` 列也走输入框：自动模式拿不到枚举候选值，空下拉比输入框更难用；要下拉就按「具名」写法
注册一个带 `options` 的 Select，再把名字写进 `editableFields`。

**`boolean` 列不进编辑态**：`dataType: 'boolean'` 生成的是 @visactor/vtable 的**原生勾选框**
（不是「平时显示文本、双击才出控件」那种列），所以给它配编辑器反而要多一层浮层、还会和格子里
原本那个框错位。GridTable 的处理是：把字段写进 `editableFields`（值随意，`true` 即可）→
该列放开只读，**单击勾选框直接切换并写回 1 / 0**（内部监听 `checkbox_state_change`，
只读列不受影响）：

```tsx
{ field: 'SSStep', title: '产能阶段', dataType: 'boolean' }
<GridTable columns={COLUMNS} editableFields={{ SSStep: true }} />
```

自动模式用的是**公共名**（`antd-input` 等），两条规矩要守住：

- 别再用 `ANTD_INPUT_EDITOR` 这类公共名注册带校验 / 带 props 的实例 —— 同名先注册者生效，
  自动模式会拿到那个实例，校验和 props 会串到所有自动列上；
- 需要校验、联动、特定 props 的列，一律注册具名实例再写字段名。

### 默认 props 与可覆盖项

编辑器内部会给控件加几个固定 props，**理解这个顺序可以避免「传了没反应」**：

| 控件 | 编辑器强制加上的 | 能否通过 props 覆盖 |
|---|---|---|
| Input | `allowClear: true`、`autoFocus`、`style`（宽高 100%） | ❌（后写，覆盖你的） |
| InputNumber | `controls: false`、`autoFocus`、`style` | ❌ |
| Select | `showSearch: true`、`getPopupContainer` | ✅（props 后写，可覆盖） |
| DatePicker | `getPopupContainer`（面板挂在单元格内） | ✅（props 后写，可覆盖） |
| 所有控件 | `value` / `onChange`（受控由编辑器接管） | ❌ |
| 所有控件 | 校验失败时注入 `status: 'error'` | ❌ |

类型上 `value` / `onChange` / `defaultValue` 已被 `Omit` 掉，写上去会编译报错。

### Input 的两点特殊说明

1. **`onSearch` 是本项目给 Input 编辑器加的扩展**（antd 只有 `Input.Search` 才有这个事件，
   普通 `Input` 传了它等于传了个永不触发的属性）。传了 `onSearch` 时编辑器会渲染成
   `Input.Search`（自带搜索按钮），回车或点搜索图标都会触发。
2. 只想要**回车触发、不要搜索按钮**，用 antd 原生的 `onPressEnter`（普通 Input 的能力，照常透传）。

### DatePicker 的值：表格里是字符串，控件里是 dayjs

转换由编辑器包办，业务不用管，但要知道两件事：

| 方向 | 行为 |
|---|---|
| 进编辑 | `toDayjs(单元格值)` —— 空值、空串、后端的 `0001-01-01` 占位、非法日期，都显示成「未选」 |
| 提交时 | dayjs 按 `valueFormat` 格式化（默认 `DATE_FORMAT` = `YYYY-MM-DD`）；没选则写回**空串** |

所以：**要「日期 + 时间」必须同时给 `showTime` 和 `valueFormat`**（如 `'YYYY-MM-DD HH:mm:ss'`），
只给 `showTime` 的话写回表格的值会被截到日。`validator` 拿到的也是格式化后的字符串（空串代表没选）。

## 四、校验：`validator`

```ts
validator?: (value, row) => string | undefined | Promise<string | undefined>
// 返回文案 = 不通过（值不写进表格），undefined = 通过；也可以返回 Promise（异步校验，见下）
```

- 时机：用户提交（失焦 / 点到别处 / 调 `endEdit()`）时，**值写进表格之前**。
- 不通过时：值不写入、编辑态不退出、控件标红、文案贴在控件下方。
- **ESC 是放弃出口**：它会把值**还原成编辑前的原值**再退出（等于这一格没改过）——
  校验没过时按 ESC 就能脱身，而且不会把当前值偷偷写进表格。
- 规则建议与保存前的整表校验**共用同一份**（参考 `services/yupai.ts` 的 `DETAIL_FIELD_RULES`），
  避免「编辑器放行、保存被拦」两边漂移。

第二个参数是**当前编辑行**（与另外三个钩子拿到的是同一个口），所以规则里能读本行其他字段：

```ts
// 本行内的跨字段规则：填了款号，款式描述就不能空
validator: (value, row) =>
    isBlank(value) && !isBlank(row.getField('StyleCode')) ? '填了款号就得填款式描述' : undefined
```

### 4.1 异步校验（调接口查数据）

规则可以返回 Promise —— **vtable 原生支持**（`IEditor.validateValue` 的类型就是
`boolean | ValidateEnum | Promise<boolean | ValidateEnum>`）：

```ts
validator: async (value) => (await styleApi.exists(String(value)) ? '该编码已被占用' : undefined),
```

实测行为：

| 阶段 | 表现 |
|---|---|
| 等待期间 | 编辑框**留在原地**、显示灰字「校验中…」；值**不会**先写进表格 |
| 等待期间连点别处 | **不会重复调接口**（vtable 的 `isValidatingValue` 挡着） |
| 结果 = 通过 | 值这时才写进表格，编辑态退出 |
| 结果 = 不通过 | 显示错误文案、留在编辑态；按 ESC 可放弃 |
| 接口报错 | 按「不通过」处理并显示错误信息（**不会静默放行**） |

所以不存在「先提交成功、接口回来才发现不合法，可编辑框已经消失」这种情况 ——
**结果回来之前 vtable 既不写值也不退出编辑**。

```ts
// 完整写法：等结果时才最终决定，onCommit 也会一起延后到那时
registerAntdInputEditor('preorder-style-code', {}, {
    validator: async (value) => (await styleApi.exists(String(value)) ? '该编码已被占用' : undefined),
    onCommit: ({ value }, row) => row.setField('StyleCode', value),
});
```

⚠️ 它只看得到**本行**：

- `row.getField()` 读的还都是**编辑前**的值（本次的新值在第一个参数 `value` 里），
  别拿它跟当前输入比对，会永远差一格；
- **跨行**规则（款号查重、尺码合计）在这里判不了 —— 放整表校验（见第七章末尾「跨行规则放哪」）。

## 五、拿「当前编辑行」：`EditorRowAccessor`

**四个钩子拿到的都是同一个行访问器**（`validator` 的第二个参数，`onStart` / `onCommit` / `onEnd` 的第一个参数），
**这是四个编辑器共用的能力，不是 Select 专属**：

```ts
interface EditorOptions<V> {
  validator?: (value: V, row: EditorRowAccessor) => string | undefined;         // 提交前校验（可读本行）
  onStart?: (row: EditorRowAccessor) => void;                                   // 进入编辑
  onCommit?: (payload: EditorCommitPayload<V>, row: EditorRowAccessor) => void; // 提交时（校验通过后）
  onEnd?: (row: EditorRowAccessor) => void;                                     // 编辑结束（含 ESC 放弃）
}

interface EditorCommitPayload<V> {
  value: V;                              // 本次提交的值
  option?: Record<string, unknown>;      // 仅 Select：被选中的那个 option 对象
}
```

### `EditorRowAccessor` 方法表

| 成员 | 说明 |
|---|---|
| `record` | 当前编辑行的原始记录对象（数据源里那一个） |
| `recordIndex` | 数据行下标（不含表头）；拿不到时为 `null`，此时写入不生效 |
| `getField(field)` | 读本行某列。⚠️ 读到的是**编辑前**的值，本次的新值在 `validator` 第 1 参 / `payload.value` 里 |
| `setField(field, value)` | 写本行某列 |
| `setFields({...})` | 一次写多列；值为 `undefined` 的字段自动跳过 |
| `endEdit()` | 结束本次编辑（等价于用户点到别处，照样走校验） |

写回是**照常派发 `change_cell_value`** 的，所以页面 `onCellValueChange` 会自动拿到这些新字段 ——
页面侧不需要额外代码，照旧 `{ ...row, [field]: value }` 展开即可。

### 四个钩子的分工

| 钩子 | 时机 | 典型用途 |
|---|---|---|
| `validator` | 提交前（值写进表格之前） | 单字段 / **本行内**跨字段校验；拿 `row` 读本行其他列 |
| `onStart` | 进入编辑、本行已就绪 | **异步回填**：把访问器存进页面闭包，等弹窗选完再写 |
| `onCommit` | 提交且校验通过 | 提交值联动其他列（含 Select 用 `option` 带出整行） |
| `onEnd` | 编辑结束（含 ESC） | 清理 `onStart` 里存下的访问器 |

## 六、必须遵守

1. **页面必须接 `onCellValueChange`。**
   GridTable 编辑时会**原地改写** record 对象，但数组引用与 state 引用都没变，React 不会重渲染。
   编辑器写回（`setField` / `setFields`）同理 —— 靠 `change_cell_value` 事件才能同步进页面 state。
   不接的话：画面可能变了，但**保存时读到的还是旧数据**。

2. **定位「哪一行」一律用行主键**（如 `_id`），不要用回调里的 `rowIndex`。
   组件接管列头排序后会给表格传排序后的数组，页面手里那份还是原始顺序，按索引改会串行。

3. **读是快照，写锚在行上。** `record` / `recordIndex` / `getField` 是拿到访问器那一刻的快照，
   `onEnd` 之后 `record` 变 `undefined`、读到的也是旧值；但 `setField` / `setFields` 锚定的是
   **行对象**（写回时按对象身份在数据源里重新定位下标），所以「弹窗开着、编辑被回车之类提前结束、
   选完再回填」照样写得进去 —— 这也是它不会串行的原因（行对象不在表里就放弃）。
   即便如此也不要长期持有、更不要存进 React state（编辑器实例全局共享，下一次编辑会覆盖锚点）。

4. **`editableFields` 是可编辑的唯一开关**（字段 → 编辑器名）。列定义里不要再挂 `editor`，
   否则只读表格仍可能因为列自带 editor 而可编辑。

5. **字段名写错编译器拦不住**。`setFields({ EmployeeName: ... })` 里写错一个字母，
   不报错、不生效、也不提示。写完最好在页面上实际点一次。

## 七、常见场景

### 7.1 Select：选项本身是一张表的行，选中带出其他字段

```ts
const employees = await employeeApi.list();

registerAntdSelectEditor(
    'preorder-employee',
    {
        options: employees.map((emp) => ({
            value: emp.EmployeeNo,
            label: emp.EmployeeName,
            data: emp,                       // 整行挂在 option 上
        })),
    },
    {
        onCommit: ({ option }, row) => {
            const emp = option?.data as EmployeeRecord | undefined;
            if (!emp) return;
            row.setFields({
                EmployeeName: emp.EmployeeName,
                DeptName: emp.DepartmentName,
            });
        },
    },
);
```

要点：**不需要**在页面维护 `value -> 整行` 的字典，也不必在下拉里 `find`。
原始行挂在 option 上，`onCommit` 的 `payload.option` 直接拿得到。

### 7.2 Input + onSearch：打开弹窗，选完回填

```tsx
// 页面组件里注册（模块级也行，但那样拿不到页面 state 的闭包）
useEffect(() => {
    registerAntdInputEditor(
        'preorder-employee-picker',
        { placeholder: '回车选择业务员', onSearch: () => setPickerOpen(true) },
        {
            onStart: (row) => { activeRowRef.current = row; },
            onEnd: () => { activeRowRef.current = null; },
        },
    );
}, []);

// QuickSelectModal 的 onSelect
const handlePickEmployee = (emp: EmployeeRecord) => {
    activeRowRef.current?.setFields({
        EmployeeName: emp.EmployeeName,
        DeptName: emp.DepartmentName,
    });
    activeRowRef.current?.endEdit();   // 选完就收工，免得编辑态与回填的数据对不上
    setPickerOpen(false);
};
```

说明：

- `onSearch` 是本项目给 Input 编辑器加的扩展（antd 普通 `Input` 没有这个事件）：
  **传了它就渲染成 `Input.Search`**，自带搜索按钮，回车或点搜索图标都会触发。
  只想回车触发、不要按钮，改用 antd 原生的 `onPressEnter`。
- 传了 `onSearch` 的编辑器，**回车只打开弹窗、不提交单元格**，编辑态会保持到选完（`endEdit()`）
  或用户点到别处。这是刻意做的：表格容器的 keydown 监听挂在编辑器**祖先**上，而且原生监听
  比 React 挂在 #root 上的冒泡派发先执行 —— 不拦的话回车会先 `completeEdit`，`onEnd` 把
  onStart 存下的访问器清掉，等 `onSearch` 拿到事件时 `activeRow` 已经是 `null`，
  选完 `setFields` 就成了静默空操作（界面一点不变，日志照打，非常难查）。编辑器在
  wrapper 的**捕获阶段**拦掉这次回车，再自己调 `onSearch`。
- `setFields` 写了**正在编辑的那一格**（比如选物料时把 `MaterialCode` 本身换掉）也没关系：
  编辑器会把输入框的值一起换掉，随后的 `endEdit()` 不会拿旧内容把它盖回去，
  不需要为了「别被盖掉」去调换 `setFields` / `endEdit` 的顺序。
- 「本行」不能存在 React state 里：编辑器实例是全局共享的，用 `useRef` 或模块级变量。
- 同一段逻辑如果用在 Select 上，把 `onSearch` 换成 `onChange` 时拿到的 `option` 即可，行访问器部分完全一样。

### 7.3 InputNumber：提交后联动计算

```ts
registerAntdNumberEditor('preorder-size', { min: 0, precision: 0 }, {
    validator: (value) => (Number(value) > 999 ? '数量过大' : undefined),
    onCommit: ({ value }, row) => {
        row.setFields({
            Number: toNumberOrZero(value),
            MSewWt: toNumberOrZero(value) * 0.5,   // 举例：按数量折算
        });
    },
});
```

页面把 `editableFields` 传 `undefined` 即整表只读（参考 V0280 的 `detailLocked`）：

```tsx
<GridTable editableFields={detailLocked ? undefined : DETAIL_EDITOR_FIELDS} ... />
```

### 7.5 DatePicker：单元格里选日期

```ts
import dayjs from 'dayjs';

registerAntdDatePickerEditor(
    'preorder-jhdate',
    {
        placeholder: '选择日期',
        // 不允许选今天之前（antd 原生能力，照常透传）
        disabledDate: (current) => (current ? current.isBefore(dayjs(), 'day') : false),
    },
    {
        validator: (value) => (value ? undefined : '请选择计划下单日期'),
        // 选完日期顺手带出别的列，一样走行访问器
        onCommit: ({ value }, row) => {
            row.setField('JHDate', value);
        },
    },
);
```

挂到列上就完了：

```tsx
<GridTable editableFields={{ JHDate: 'preorder-jhdate' }} ... />
```

值的转换（字符串 ↔ dayjs）由编辑器负责，页面只需要保证这一列填给 `editableFields` 时用的字段名与表格数据里的字段名一致。

### 7.6 跨行规则（查重、尺码合计）放哪 —— **别放 `validator`**

`validator` 拿到的是**本行**，判不了「这一行填的款号在明细里是不是已经出现过」。
这类规则不要靠编辑器补能力，而是放**整表校验**：`services/yupai.ts` 的
`validateYupaiOrderDetailRows(rows)` —— 它一次拿到全部行，返回「行主键 → 字段 → 文案」。

页面每次编辑后的流程本来就是：

```tsx
setDetailRows(nextRows);
setCellErrors(toCellErrors(validateYupaiOrderDetailRows(nextRows)));   // 每次编辑后都跑
```

所以把跨行规则加进整表校验，**时序上就等于「编辑完立刻检测」**，
还顺带白拿三样：格子标红（`cellStyle`）、悬停看原因（`cellTooltip`）、保存前拦截。

⛔ 别在 `validator` 里另写一份：两边规则一旦不同步，就会变成
「编辑器放行了、保存时又被拦下」，用户完全摸不着头脑。

## 八、限制与已知边界

| 限制 | 说明 / 应对 |
|---|---|
| `options` / `props` 是**注册时固定**的 | 编辑器实例全局共享，无法按行给不同 options。需要不同选项集时注册多个具名实例。 |
| 同名注册**先到先得** | 第二次注册被静默忽略。跨页面复用同一名字会拿到第一个页面的 props。 |
| 写回触发的事件会重跑页面的 `onCellValueChange` | 一次写 3 列 → 页面回调被调 3 次（每次一条字段）。行数不多时可忽略；回调里避免重活。 |
| 值没变时不派发事件 | `oldValue !== changedValue` 才派发，所以「选回原值」不会有回调（也不需要）。 |
| `recordIndex` 是**数据源下标** | 排序后与页面数组下标不一致。业务侧统一用行主键定位，别自己换算。 |
| 表格不支持时静默降级 | 拿不到 `getCellRawRecord` / `getRecordIndexByCell` 时 `recordIndex` 为 `null`，写回不生效也不报错。 |
| 日期时间是字符串，不是 dayjs | 表格数据里存字符串；`getField('JHDate')` 拿到的也是字符串，要算日期先 `toDayjs()`。 |
| `validator` 只拿得到**本行** | 跨行规则（款号查重、尺码合计）放整表校验 `validateYupaiOrderDetailRows`；两处各写一份必然漂移。 |
| 自动模式（`true` / `'auto'`）只按 `dataType` 选控件 | 没有校验、没有 props；`tag` 也只能用输入框。要这些就注册具名实例。 |
| `boolean` 列没有 `validator` / `onCommit` | 它走的是原生勾选切换（`changeCellValueByRecord`），只保证结果写回 `1` / `0` 并触发 `onCellValueChange`；要校验就在保存前做整表校验。 |
| `row.getField()` 读的是**编辑前**的值 | 这一格的新值在 `validator` 第 1 参 / `onCommit` 的 `payload.value` 里。 |
| 异步校验等待期间 | vtable 会挡掉重复的 `completeEdit`（实测：连点别处不会重复调接口），代价是这段时间表格的编辑动作要等它结束 —— 接口别做重活、记得设超时。 |

## 十、速查卡

```
注册      registerAntdXxxEditor(名字, antdProps, { validator, onStart, onCommit, onEnd })
开关      <GridTable editableFields={{ 字段: 名字 }} />
自动      editableFields={{ 字段: true }} → 按 dataType 挑默认编辑器
布尔      dataType:'boolean' 的列不用编辑器：editableFields={{ 字段: true }} 就变成
          原生勾选框可点，单击直接切换并写回 1 / 0（不走编辑态、没有 validator）
校验      validator: (value, row) => 文案 | undefined   // 返回文案 = 拦住提交，值不进表格
本行      四个钩子都拿 EditorRowAccessor（validator 是第 2 个参数）
          读 getField（读到的是编辑前的值）/ 写 setField·setFields / 收工 endEdit()
跨行      款号查重、尺码合计这类判不了的 → 整表校验 validateYupaiOrderDetailRows
          别写进 validator：两边规则会漂移
异步      校验可返回 Promise（调接口）：等待中显示「校验中…」、连点不会重复调接口、
          结果回来才写值/退出（不会「先写进去、后来才发现不合法」）
ESC       放弃这一格：值还原成编辑前的原值再退出（不会把当前值偷偷写进表格）
取值      Select 的选中项在 onCommit 的 payload.option（原始行挂在 option.data 上）
日期      DatePicker 编辑器：进编辑 toDayjs、提交按 valueFormat 转字符串（空给空串）
          要日期+时间就同时给 showTime 与 valueFormat，只给 showTime 会被截到日
弹窗      Input 传 onSearch（渲染成 Input.Search）→ 打开弹窗
          → activeRow.setFields({...}) → activeRow.endEdit()
页面      onCellValueChange 里按行主键定位，{ ...row, [field]: value }
禁忌      ❌ 用 rowIndex 定位   ❌ 复用公共名字配校验   ❌ 忘了接 onCellValueChange
          ❌ 长期持有访问器     ❌ 字段名写错（编译器拦不住）
          ❌ 在 validator 里判跨行（它只看得到本行）
```
