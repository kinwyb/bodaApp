# 页面命令条用法（CommandBar 标准结构）

> 基准版本：`main` @ `67ae1f0`（2026-11-03）
> 样板页面：`src/pages/views/V0189/V0279/V0280/`（多组命令）、`src/pages/views/V0277/V0354/`（单组命令）
> 通用层：`src/components/CommandBar.tsx`、`src/components/commands/`

---

## 一、一句话结论

一个页面要加命令条（顶部那排「图标在上、文字在下」的按钮），就建一个 `command/` 目录：

```
<页面目录>/command/
  types.ts          本页命令的依赖契约（业务字段 + Context + Factory 类型）
  add.tsx           一个命令一个文件，导出 CommandFactory 常量
  edit.tsx
  delete.tsx
  ...
  index.ts          COMMAND_ORDER（顺序）+ 工厂数组 + useXxxCommands(context)
```

页面本身**不写命令**，只做两件事：把状态与动作装成 context，渲染 `<CommandBar view={view} items={commands}/>`。

这样拆的三个理由：**一个按钮一个文件，改哪个找哪个**；依赖靠类型约束（哪个命令要什么，`.deps` 里一眼看到）；
命令条与界面桥同源（桥直接读 `commands` 生成 `actions`），不会出现「屏幕上有按钮、模型看不见」。

---

## 二、三层分工

| 层 | 文件 | 职责 | 不该做的事 |
|---|---|---|---|
| 契约 | `command/types.ts` | 声明 `FormMode`、本页业务依赖、`Context`、`Factory` 类型 | 不写实现 |
| 命令 | `command/xxx.tsx` | 一个按钮：图标、文案、什么时候禁用、点了干什么 | 不调 hook、不读页面 state（只能读 context） |
| 装配 | `command/index.ts` | 决定顺序与分组，导出 `useXxxCommands(context)` | 不写业务 |
| 页面 | `index.tsx` | `useMemo` 组装 context、渲染 `<CommandBar>` | 不写按钮逻辑 |

## 三、复制即用：四段代码

### 3.1 `command/types.ts`

```ts
import type {CommandContext, CommandFactory} from '@/components/commands';
import type {PackBomMatrix} from '@/api/schemas/nc/bomMatrix.ts';

/** 表单模式：add 空表 / edit 改原记录 / view 只读 / copy 带出数据但落成新记录 */
export type FormMode = 'add' | 'edit' | 'view' | 'copy';

/** 本页业务依赖：只写「按钮需要、通用层不认识」的字段 */
export interface PackBomMatrixCommandDeps {
    /** 当前激活行（鼠标最后点选的那一行）；没有则为 null */
    activeRow: PackBomMatrix | null;
    /** 有没有选中行 —— 驱动 disabled */
    hasSelection: boolean;
    /** 按当前条件重新加载列表 */
    reload: () => Promise<void> | void;
    /** 打开表单弹窗（mode 语义见 FormMode） */
    openForm: (mode: FormMode, record: PackBomMatrix | null) => void;
}

/** 本页命令上下文 = 通用层的框架能力（message / modal / tableRef）+ 上面的业务依赖 */
export type PackBomMatrixCommandContext = CommandContext<PackBomMatrixCommandDeps>;

/** 本页命令工厂 */
export type PackBomMatrixCommandFactory = CommandFactory<PackBomMatrixCommandContext>;
```

`CommandContext<T>` 自带三个框架能力，**不要**在业务依赖里重复声明：

| 字段 | 类型 | 用途 |
|---|---|---|
| `message` | antd `App.useApp().message` | 轻提示 |
| `modal` | antd `App.useApp().modal` | 确认框 / 弹窗 |
| `tableRef` | `RefObject<GridTableApi \| null>` | 直接操作表格（清空选中、取选中行） |

### 3.2 一个命令 `command/edit.tsx`

```tsx
import {EditOutlined} from '@ant-design/icons';
import type {PackBomMatrixCommandFactory} from './types';

/** 编辑：取选中的那一行，打开编辑表单 */
export const editCommand: PackBomMatrixCommandFactory = ({message, activeRow, hasSelection, openForm}) => ({
    key: 'edit',
    label: '编辑',
    icon: <EditOutlined/>,
    disabled: !hasSelection,
    onClick: () => {
        if (!activeRow) {
            void message.warning('请先选中一行');
            return;
        }
        openForm('edit', activeRow);
    },
});
```

不需要参数的命令（`add`、`refresh`）直接解构用：

```tsx
export const refreshCommand: PackBomMatrixCommandFactory = ({reload}) => ({
    key: 'refresh',
    label: '刷新',
    icon: <ReloadOutlined/>,
    dividerBefore: true,
    onClick: () => void reload(),
});
```

### 3.3 `command/index.ts`

```ts
import {useMemo} from 'react';
import type {CommandItem} from '@/components/CommandBar';
import {useCommandGroups} from '@/components/commands';
import {addCommand} from './add';
import {editCommand} from './edit';
import {refreshCommand} from './refresh';
import type {PackBomMatrixCommandContext, PackBomMatrixCommandFactory} from './types';

export type {FormMode, PackBomMatrixCommandContext, PackBomMatrixCommandDeps} from './types';

/**
 * 命令条从左到右的顺序（写命令的 key）。
 * 加按钮 / 挪位置只改这张表，不必为了插到中间去硬拆一组。
 * 漏写 key 不会丢按钮（排到末尾），开发环境会 console.warn 提醒补表。
 */
const COMMAND_ORDER = ['add', 'edit', 'refresh'] as const;

/** 模块级常量：保住引用稳定，命令条才只在 context 变化时重建 */
const packBomMatrixCommandFactories: PackBomMatrixCommandFactory[] = [
    addCommand,
    editCommand,
    refreshCommand,
];

export function usePackBomMatrixCommands(context: PackBomMatrixCommandContext): CommandItem[] {
    // groups 必须 useMemo：useCommandGroups 按它缓存，每帧新数组会让缓存全失效
    const groups = useMemo(() => [{context, factories: packBomMatrixCommandFactories}], [context]);
    return useCommandGroups(groups, {order: COMMAND_ORDER});
}
```

## 四、必须遵守的六条

### 1. 命令工厂必须是纯函数

工厂在 `useCommands` / `useCommandGroups` 的 `useMemo` 回调里求值。**工厂内部再调 hook** 就是
「hook 回调里调 hook」，会报 `Do not call Hooks inside ...` 并打乱外层 hook 顺序 —— 连带把后面
无关的 `useMemo` 报成 `deps changed size`（别去查那个 useMemo）。

### 2. 顺序与分组是两件事

顺序写在 `COMMAND_ORDER`（字符串 key 数组），分组由 `groups` 决定。**不要为了把按钮插到中间去拆组**。
只有一个 context 且不需要自定义顺序时，可以退化成 `useCommands(context, factories)`（无 order 表）。

### 3. 先建 context 对象，再交给 hook

```tsx
// ✅ 对：ref 只是对象的一个属性，hook 里不会在 render 期读 current
const ctx = useMemo<XxxCommandContext>(() => ({message, modal, tableRef, ...}), [...]);
const commands = useXxxCommands(ctx);

// ❌ 错：等价于 render 期把 ref 当参数递给普通函数
const commands = useMemo(() => createXxxCommands({..., tableRef}), [...]);
```

后者会被 oxlint 的 `react(refs)` 拦下：`Cannot access refs during render`。

### 4. `disabled` 的判据只写一处

需要「先选中一行」的按钮统一用 `disabled: !hasSelection`，不要一个用 `!activeRow`、另一个用
`rows.length === 0` —— 会出现「删除灰着、编辑却能点」这种自相矛盾的状态。

命令里再补一次 `if (!activeRow)` 是给旁路兜底（快捷键、桥直接调命令），不是重复判断。

### 5. 命令能自己干的事就自己干

调接口、弹确认框、失败重试都在命令文件里（`message` / `modal` 都从 context 拿）。
只有**依赖页面 state** 的才进 deps：打开表单弹窗（`openForm`）、跳另一个页面（`openProcessMatrix`）、
重新查库（`reload`）。

判据：**这个动作需要页面的 useState 吗？** 要 → 进 deps；不要 → 命令自己实现。

### 6. 权限字段别乱填

| 字段 | 行为 |
|---|---|
| `permission: '编辑'` | 按菜单里该页面下**叫这个名字**的按钮判权；**菜单里没有 → 整个按钮不渲染** |
| `menuCode: 'A1DE…'` | 直接指定 MenuCode，优先级高于 permission |

所以「先摆按钮、后接权限」时**不要填 `permission`**：菜单里没配该按钮，按钮会直接消失，
表现像「代码没生效」。确认菜单里真有这个按钮名（或拿到 MenuCode）再填。

## 五、与界面桥对接（agent 能看见这排按钮）

命令条与桥**同源**：不要另写一份动作表。

`bridged.ts` 里：

```ts
import type {CommandItem} from '@/components/CommandBar';

export type XxxBridgeContext = {
    // ……
    /** 页面命令条：动作表直接由它生成，命令 ID 就是 CommandItem.key */
    commands: CommandItem[];
};

// 快照
actions: [
    ...read().commands.map((item) => ({
        id: item.key,
        label: item.label,
        group: 'toolbar' as const,
        danger: item.danger,
        disabled: item.disabled,
        disabledReason: item.disabled ? '需要先选中一行：用 data.select' : undefined,
    })),
    // ……表格桥的动作
],

// 处理函数：直接调按钮自己的 onClick，只包一层回执
read().commands.forEach((item) => {
    if (!item.onClick) return;
    handlers[item.key] = () => {
        // 命令项随选中行重新生成，闭包里那个可能过期，执行时按 key 重新取
        const latest = read().commands.find((cmd) => cmd.key === item.key) ?? item;
        if (latest.disabled) return `「${latest.label}」现在不可用`;
        latest.onClick?.();
        return `已执行：${latest.label}`;
    };
});
```

注意：`disabled` **不进结构指纹**（见 `ui-bridge/handler.ts` 的 `structureKey`），所以选中行变化只发补丁，
不会整页重发快照 —— 可以放心把它放进 actions。

## 六、新增一个按钮（四步）

1. 在 `command/` 下新建 `xxx.tsx`，导出 `xxxCommand: XxxCommandFactory`（图标 + label + onClick）；
2. 需要新依赖 → 在 `types.ts` 的 `XxxCommandDeps` 里加字段，并在页面 context 里补上实现；
3. 在 `command/index.ts` 的工厂数组里注册，并把 key 写进 `COMMAND_ORDER` 的对应位置；
4. 跑 `npx tsc -b` + `npx oxlint <页面目录>`。桥那边不用动 —— `actions` 自动多一条。

## 七、检查清单

- [ ] `command/` 下一个命令一个文件，文件名与 `key` 对得上（`delete.tsx` → `'delete'`）
- [ ] `COMMAND_ORDER` 里每个 key 都写了（dev 环境漏写会 warn）
- [ ] 工厂是纯函数，里面没有 `useXxx()` / `useMemo` / `useCallback`
- [ ] 页面是「先 `useMemo` 建 context，再交给 `useXxxCommands(ctx)`」
- [ ] `message` / `modal` 来自 `App.useApp()`，不是 `import {message} from 'antd'`
- [ ] 需要选中行的按钮统一 `disabled: !hasSelection`
- [ ] `permission` 只在菜单里确有该按钮时才填
- [ ] 桥的 `ctx.commands` 与页面渲染的是同一份 `commands`
- [ ] `npx tsc -b` 无错、`npx oxlint <目录>` 无 error

## 八、常见错误对照

| 现象 | 原因 | 修法 |
|---|---|---|
| `Do not call Hooks inside ...`，随后报 `deps changed size` | 工厂里调了 hook | 工厂改成纯函数，依赖从 context 拿 |
| `Cannot access refs during render` | `useMemo(() => factory({..., tableRef}), [...])` | 拆两步：先建 context，再交给 hook |
| 按钮点了没反应 | `onClick` 里 `if (!target) return` 静默返回 | 至少 `message.warning('请先选中一行')` |
| 按钮直接不出现 | 填了 `permission` 但菜单里没有这个按钮名 | 去掉 `permission`，或改用 `menuCode` |
| 顺序不是想要的 | 只调了工厂数组顺序，没改 `COMMAND_ORDER` | 顺序只认 `COMMAND_ORDER` |
| 每次渲染命令条都重建 | `groups` 没 `useMemo`，或工厂数组写在组件里 | 一个是 `useMemo`，一个是模块级常量 |
| agent 看不到新按钮 | 桥的 actions 没读 `commands` | 按第五节接上 |
