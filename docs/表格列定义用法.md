# 表格列定义用法（AppColumnDef / buildColumns）

> 代码路径：`src/components/vtable/columnBuilder.ts`
> 基准版本：`main`（2026-10-19，`fieldFormat` / `style` 提为一级属性后）
> 说明：本文只讲**怎么用**与**合并规则**。实现细节看 `columnBuilder.ts` 里的注释。

---

## 一、一句话结论

列定义只做三件事：**用 `dataType` 声明它是什么**，需要时覆盖 `fieldFormat`（显示值）、叠加 `style`（样式），最后交给 `buildColumns`：

```tsx
const columns = useMemo(() => buildColumns(COLUMNS), []);

<VTable columns={columns} records={rows} />
```

三条铁律：

| 属性 | 语义 | 与默认值的关系 |
|---|---|---|
| `fieldFormat` | 单元格**显示什么** | **替换**（写了就不再用 dataType 的默认格式） |
| `style` | 单元格**长什么样** | **合并**（默认样式打底，同名字段以你为准） |
| `columnProps` | VTable 其它列配置的兜底口子 | **整体覆盖**（不合并，不推荐再往里写 style / fieldFormat） |

---

## 二、导入

```ts
// 函数 + 类型都从子路径导入（index.ts 只导出组件与类型，原因见该文件注释）
import { buildColumns, type AppColumnDef } from '@/components/vtable/columnBuilder';
```

`COLUMNS` 建议写成模块级常量（`AppColumnDef[]`），需要按业务动态增减时再在页面里拼。

---

## 三、`AppColumnDef` 字段表

| 字段 | 类型 | 说明 |
|---|---|---|
| `field` | `string` | 数据字段名，**必填** |
| `title` | `string` | 列标题，**必填** |
| `width` | `number` | 列宽（px），不传由 VTable 分配 |
| `dataType` | `'text' \| 'number' \| 'date' \| 'datetime' \| 'boolean' \| 'tag'` | 决定控件、默认格式与对齐，默认 `text` |
| `precision` | `number` | 只对 `number`：小数位，`0` 表示整数 |
| `tagMap` | `Record<string, string \| { label, color }>` | 只对 `tag`：值 → 文案（可带文字颜色） |
| `booleanText` | `[string, string]` | 只对 `boolean`：勾选框右侧文案，顺序是 **[选中, 未选中]** |
| `sortable` | `boolean` | 列头显示排序（具体排序行为由表格的排序配置决定） |
| `fieldFormat` | `AppColumnFieldFormat` | 显示格式，覆盖 dataType 默认 |
| `style` | `AppColumnStyle` | 单元格样式，对象或函数，与默认样式合并 |
| `columnProps` | `Record<string, unknown>` | 透传 VTable 其它列配置，最后执行、整体覆盖 |

## 四、`dataType` 速查

| dataType | 渲染 | 默认 fieldFormat | 默认 style |
|---|---|---|---|
| `text` | 文本 | 无（原始值） | 无 |
| `number` | 文本 | 有 `precision` 时 `toFixed(precision)`，否则原始值 | `{ textAlign: 'right' }` |
| `date` | 文本 | `formatDate()` → `YYYY-MM-DD`，空值 / `0001-01-01` 占位显示空串 | 无 |
| `datetime` | 文本 | `formatDateTime()` → `YYYY-MM-DD HH:mm:ss`，空值同上 | 无 |
| `boolean` | **只读**勾选框（`disable: true`） | 返回 `{ checked, disable, text? }` | 函数：居中 + 白底 + 只读复选框配色 |
| `tag` | 文本 | 按 `tagMap` 映射文案（没配的显示原值） | 函数：按值映射文字颜色 |

```ts
const COLUMNS: AppColumnDef[] = [
  { field: 'StyleCode', title: '款号', width: 110 },                                 // text
  { field: 'Qty', title: '总数量', width: 90, dataType: 'number', sortable: true },   // 右对齐
  { field: 'Rate', title: '达成率', width: 90, dataType: 'number', precision: 2 },     // 两位小数
  { field: 'YPDate', title: '预订日期', width: 100, dataType: 'date' },
  { field: 'CreateTime', title: '创建时间', width: 150, dataType: 'datetime' },
  { field: 'SSStep', title: '产能阶段', width: 100, dataType: 'boolean' },             // 只有勾选框
  // 勾选框右侧带文案
  { field: 'QMStep', title: '全码样阶段', width: 120, dataType: 'boolean', booleanText: ['已排产', '未排产'] },
  {
    field: 'State', title: '状态', width: 90, dataType: 'tag',
    // 字符串简写 = 只有文案；对象写法才指定颜色
    tagMap: { 1: '待审核', 2: { label: '已通过', color: '#389e0d' } },
  },
];
```

> `tagMap` 的键最终按 `String(value)` 匹配，对象字面量的数字键本身就是字符串，所以 `{ 1: '待审核' }` 能匹配数据里的 `1`。

## 五、`fieldFormat`：覆盖显示值

写了就**不再用** dataType 的默认格式。返回值是什么就显示什么。

```ts
// 1) 加单位
{ field: 'Qty', title: '数量', dataType: 'number', fieldFormat: (r) => `${r.Qty} 件` }

// 2) 换日期粒度（date 默认到日，这里只要年月）
{ field: 'YPDate', title: '预订月份', dataType: 'date',
  fieldFormat: (r) => String(r.YPDate ?? '').slice(0, 7) }

// 3) 空值 / 0 显示成占位符（比满屏 0 好读）
{ field: 'MWeight', title: '克重', dataType: 'number',
  fieldFormat: (r) => (Number(r.MWeight) > 0 ? r.MWeight : '-') }

// 4) 码表转中文（参数是 any，可以标成具体行类型）
{ field: 'KnitOrgID', title: '织造产地', width: 90,
  fieldFormat: (record: YupaiOrder) => ORG_NAME(record.KnitOrgID) }
```

签名（VTable 的 `FieldGetter`）：

```ts
(record: any, col?: number, row?: number, table?: BaseTableAPI) => any
```

也支持 `{ get, set }` 形态（`FieldAssessor`），业务里暂时没用到。

**注意**：`fieldFormat` 只影响显示。要参与条件判断、提交给后端的，仍然是行数据里的原值。

## 六、`style`：对象与函数

### 6.1 传对象（静态样式）

```ts
// number 默认右对齐，这里加底色与加粗，对齐不受影响
{ field: 'Qty', title: '总数量', width: 90, dataType: 'number',
  style: { bgColor: '#fffbe6', fontWeight: 'bold' } }

{ field: 'Memo', title: '备注', width: 190,
  style: { color: '#8c8c8c', fontStyle: 'italic' } }
```

### 6.2 传函数（按行 / 按值算）

参数是 `StylePropertyFunctionArg`：

```ts
{
  row: number;               // 表格行号（含表头，业务行号 = row - table.columnHeaderLevelCount）
  col: number;
  table: BaseTableAPI;
  value?: FieldData;
  dataValue?: FieldData;     // 当前单元格的数据值
  percentile?: number;
  cellHeaderPaths?: ICellHeaderPaths;
}
```

```ts
{
  field: 'XDRate', title: '下单把握度', width: 100, dataType: 'number',
  style: ({ dataValue, row }) => ({
    ...(Number(dataValue) < 60 ? { color: '#cf1322' } : {}),   // 低于 60 标红
    bgColor: row % 2 ? '#fafafa' : '#ffffff',                  // 斑马纹
  }),
}
```

### 6.3 与默认样式合并（重点）

`style` **不是整份替换**，而是「默认样式打底、你的覆盖同名项」：

| 列定义 | dataType 默认 | 实际生效 |
|---|---|---|
| `number` + `style: { bgColor: '#eee' }` | `{ textAlign: 'right' }` | `{ textAlign: 'right', bgColor: '#eee' }` |
| `tag` + `style: { fontWeight: 'bold' }` | 函数（按值上色） | 函数：先按值上色，再叠 `fontWeight` |
| `boolean` + `style: { bgColor }` | 函数（居中 + 只读框） | 居中、只读框保留，底色被覆盖 |
| 只写 `columnProps.style` | — | 整份替换（不合并，见第八节） |

实现上：两边都是对象时浅合并；有一边是函数时包一层，先算默认再叠自定义。所以给 `tag` 列加个字重，不会把按值上色顶掉。

### 6.4 与 `cellStyle` / 统计行的关系

`VTable` 组件内部会再包一层（`VTable.tsx` 的 `decorate`）：把列的 `style` 作为 `base`，然后**按顺序短路**：

```
base = 列的 style（对象或函数的结果）
├─ 统计行        → 叠加灰底加粗后直接返回（不再往下走）
├─ 展开行        → 叠加"内容贴顶"的内边距后直接返回
└─ 页面 cellStyle → 有返回就叠加（语义化字段翻译后覆盖 base）
```

所以：统计行和展开行的样式由框架接管，页面 `cellStyle` 在那两种行上不生效。页面级「某行某字段提醒」用 `cellStyle` prop 更合适，列 `style` 只表达这列的固有样式。

## 七、`boolean` 与 `tag` 专项

### 7.1 自定义勾选框外观

```ts
{
  field: 'SSStep', title: '产能阶段', width: 110, dataType: 'boolean',
  booleanText: ['已排产', '未排产'],
  style: ({ dataValue }) => ({
    bgColor: Number(dataValue) === 1 ? '#f6ffed' : '#ffffff',
    // checkboxStyle 能直接写，AppColumnStyle 已并入 VTable 的 CheckboxStyleOption
    checkboxStyle: { checkedFill: '#52c41a', checkedStroke: '#52c41a', size: 14 },
  }),
}
```

常用 `checkboxStyle` 字段：`defaultFill` / `defaultStroke` / `checkedFill` / `checkedStroke` / `disableFill` / `disableStroke` / `disableCheckedFill` / `disableCheckedStroke` / `size` / `spaceBetweenTextAndIcon`。

`dataType: 'boolean'` 的勾选框是**只读展示**（`disable: () => true`）。要能编辑，走可编辑表格（`editableFields` + 编辑器），别指望点这个框。

### 7.2 `tag` 配颜色

```ts
{ field: 'State', title: '状态', dataType: 'tag',
  tagMap: { 1: '待审核', 2: { label: '已通过', color: '#389e0d' } },
  style: { fontWeight: 'bold' } }   // 颜色按 tagMap 逐值走，字重来自这里
```

没配 `color` 的项**不返回 color**，文字沿用主题默认色（和底色自然一致，不写死黑/白）。

## 八、`columnProps`：兜底口子

`columnProps` 直接展开进 VTable 的列配置，位于最后 —— **整体覆盖，不合并**。用于 `AppColumnDef` 没抽象的一级属性：

```ts
{
  field: 'OrderCode', title: '订单号', width: 130,
  columnProps: { headerStyle: { bgColor: '#fafafa', fontWeight: 'bold' } },
}
```

常见可用项：`headerStyle`（表头样式）、`cellType`（非 text/checkbox 的单元格类型）、`editor`、`mergeCell`、`tree`、`hide`、`disableColumnResize` 等，完整清单看 `ColumnsDefine`。

**别再往 `columnProps` 里写 `style` / `fieldFormat`**：写了就是整份替换，默认右对齐、只读框样式会一起丢。全仓库已无这种写法。

---

## 九、批量生成列

尺码这种重复结构用 `map` 生成：

```ts
const SIZES: AppColumnDef[] = ['S', 'M', 'L', 'XL'].map((title, index) => ({
  field: `Size${index + 1}`,
  title,
  width: 70,
  dataType: 'number' as const,     // ⚠️ 不加 as const 会被推成 string
  style: { bgColor: '#fafafa' },
  fieldFormat: (r: Record<string, unknown>) => {
    const value = Number(r[`Size${index + 1}`]);
    return value > 0 ? value : '';
  },
}));
```

## 十、覆盖优先级

从低到高：

```
① base（field / title / width / sortable）
② dataType 推导（style / fieldFormat / cellType / checked / disable）
③ def.fieldFormat（替换）        def.style（合并进 ②）
④ columnProps（整体覆盖 ①②③）
⑤ VTable 运行时装饰（统计行 / 展开行短路优先，其后才是页面 cellStyle）
```

放一张对照：

| 你写了 | 结果 |
|---|---|
| `dataType: 'number'` 且 `fieldFormat` | 用你的格式，右对齐仍保留 |
| `dataType: 'number'` 且 `style: { bgColor }` | 右对齐 + 你的底色 |
| `dataType: 'tag'` 且 `style: { fontWeight }` | 按值上色 + 你的字重 |
| `style` 且 `columnProps.style` | 只用 `columnProps.style` |
| `fieldFormat` 且 `columnProps.fieldFormat` | 只用 `columnProps.fieldFormat` |

## 十一、类型是怎么来的

```ts
// 显示值类型：从文本列的 fieldFormat 属性反查，再剥掉可选带来的 undefined
export type AppColumnFieldFormat = NonNullable<TextColumnDefine['fieldFormat']>;
//   = FieldGetter | FieldAssessor
//   = ((record, col?, row?, table?) => any) | { get: FieldGetter; set: FieldSetter }

// 样式类型：文本列的 style（对象或函数）+ 复选框列专有的 checkboxStyle
export type AppColumnStyle =
  | NonNullable<TextColumnDefine['style']>   // ITextStyleOption | ((args: StylePropertyFunctionArg) => ITextStyleOption)
  | TYPES.CheckboxStyleOption                // 含 checkboxStyle / size 等
  | ((args: TYPES.StylePropertyFunctionArg) => TYPES.ITextStyleOption | TYPES.CheckboxStyleOption);
```

- `NonNullable<T>` 是必要的：`fieldFormat?: X` 本身隐含 `undefined`，不剥掉的话把该类型当「值类型」用（参数标注、`Record<string, AppColumnFieldFormat>`）时处处要补 `| undefined`。
- 之所以从 `TextColumnDefine` 取而不直接用 `TYPES.FieldFormat`：两者**完全等价**（已用 TS 编译器 API 验证），取列属性是为了「跟列定义同源」，将来 VTable 调整该属性类型时自动跟随。想更直白也可以改成 `TYPES.FieldFormat`。
- number / date / datetime / tag 最终都由文本单元渲染，boolean 是 checkbox 单元，两者都 `extends IBasicColumnBodyDefine`，`fieldFormat` 同源，所以用文本列当基准覆盖全部 `dataType`。

## 十二、踩坑清单

1. **`map` 生成列必须 `dataType: 'number' as const`**，否则字面量被放宽成 `string`，类型检查不过。
2. **`style` 不要写进 `columnProps`**：那是整份替换，默认对齐 / 只读复选框样式会丢；直接写一级 `style` 才会合并。
3. **`booleanText` 顺序是 `[选中, 未选中]`**，写反了文案不会报错，只是显示颠倒。
4. **`precision: 0` 有效**（内部用 `!== undefined` 判断），想要整数显示就显式写 0，别指望默认。
5. **页面里的 `columns` 要稳定引用**（模块级常量或 `useMemo`）：`VTable` 内部 `finalColumns` 依赖 `columns` 引用，每次渲染新建数组会让它重新装饰列并 `updateOption` 空转。
6. **`tagMap` 的键按 `String(value ?? '')` 查**：`{ 1: 'x' }` 与 `{ '1': 'x' }` 等价、布尔值也能命中；但空值统一折成 `''`，所以配 `undefined` / `null` 键永远不会命中，要配空字符串键（`{ '': '未设置' }`）。
7. **`fieldFormat` 只管显示**：排序、校验、提交都用行数据原值，别把业务逻辑塞进格式函数里做副作用。
8. **给 `date` / `datetime` 列自定义 `fieldFormat` 就绕开了默认格式化**：后端用 `0001-01-01` 表示空日期，这时要自己挡（判断 `startsWith(EMPTY_DATE_PREFIX)`），否则会把占位日期显示出来。

## 十三、完整示例（预订单列表）

```ts
import type { AppColumnDef } from '@/components/vtable/columnBuilder';
import { type YupaiOrder, YupaiMachineSizeHeader } from '@/api';
import { ORG_NAME } from '@/store/orgs.ts';

export const COLUMNS: AppColumnDef[] = [
  { field: 'WorkPlace', title: '产地', width: 90 },
  { field: 'YPDate', title: '预订日期', width: 100, dataType: 'date', sortable: true },
  // 码表转中文：只覆盖显示，排序仍按 ID
  { field: 'KnitOrgID', title: '织造产地', width: 90,
    fieldFormat: (record: YupaiOrder) => ORG_NAME(record.KnitOrgID) },
  { field: 'Qty', title: '总数量', width: 90, dataType: 'number', sortable: true },
  // 纯样式：number 的右对齐保留
  { field: 'XDRate', title: '下单把握度', width: 95, style: { textAlign: 'right' } },
  // 阶段列
  { field: 'SSStep', title: '产能阶段', width: 100, dataType: 'boolean' },
  { field: 'QMStep', title: '全码样阶段', width: 110, dataType: 'boolean' },
  // 批量尺码列：0 与空值都不显示（number 默认右对齐，不用再写 style）
  ...YupaiMachineSizeHeader.map((title, index) => ({
    field: `MCSize${index + 1}`,
    title,
    width: 82,
    dataType: 'number' as const,
    fieldFormat: (record: YupaiOrder) => {
      const value = record[`MCSize${index + 1}`];
      return value === null || value === undefined || value === '' ? '' : Number(value) > 0 ? value : '';
    },
  })),
];
```

对应的详情表格（可编辑）只需在列定义外挂 `editableFields`，列本身仍然只声明「展示成什么」（完整实现在 `V0280/models/yupaiOrderEditColumns.ts`）：

```tsx
const columns = useMemo(() => buildColumns(DETAIL_COLUMNS), []);

<VTable columns={columns} records={rows} editableFields={DETAIL_EDITOR_FIELDS} />
```
