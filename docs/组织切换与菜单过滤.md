# 组织切换与菜单过滤

> 基准版本：`main` @ `af8e84f`（2026-11-12）
> 说明：文中行号基于该版本，后续改动会导致行号漂移，函数名与文件路径相对稳定。
> 关联文档：[权限模块代码路径](权限模块代码路径.md)。权限过滤（用户权限树）与组织过滤
> （服务器组织）是**两道独立的闸门**，菜单要同时通过才会显示。

---

## 一、一句话结论

「我现在连的是哪个组织」只有**一个权威来源**：`Service-Org` 响应头。

- **web**：同源部署，组织由部署自己声明 —— nginx 给每个响应加 `Service-Org: <OrgID>`；
- **app**：设置窗口切换组织 = 换应用内代理的 API 上游，Go 侧再 dispatch
  `boda-org-changed` 事件把新组织告诉页面。

菜单过滤、顶栏组织 Tag、切换后的菜单重拉与页签重置，全部读同一份运行时状态
（`src/utils/service-org.ts` 的 `{orgId, epoch}`），没有第二套判定。

**不用 `userInfo.OrgID`**：那是「用户所属组织」，跨组织登录时会和服务器组织不一致；
组织是「哪台服务器」的属性，不是「哪个人」的属性。

---

## 二、行为矩阵

| 场景 | orgId | 菜单组织过滤 | 顶栏 Tag |
|---|---|---|---|
| release + nginx 配了头 | 头里的值 | 按 `UseOrgs` 过滤 | 显示，名称经 `ORG_NAME` 转换 |
| release + 没配头 | 空 | fail-open，不过滤 | 不显示 |
| debug（本地 dev / mock） | 通常空（mock 不发头） | 不过滤（调试豁免） | 不显示 |
| app 设置窗口切换后 | 新组织 | 按新组织过滤 | 显示并即时更新 |

fail-open 是刻意的：没配头的存量部署保持原样，不会因为缺配置把菜单藏没。

## 三、数据流

```
nginx（每台组织的部署）                    app 设置窗口选中组织
  add_header Service-Org … always           switchOrg()            app/org.go
        │                                    ├─ 写 settings.json（仅 APIBaseURL/OrgID）
        │ 响应头                              ├─ retargetAPI 换代理上游   app/proxy.go
        ▼                                    └─ page.Eval dispatch boda-org-changed
src/api/request.ts                                  │
  captureServiceOrg(response.headers)               ▼
        │                              notifyOrgSwitched(orgId)  epoch+1
        ▼                                           │
src/utils/service-org.ts   snapshot {orgId, epoch} ◄─┘
        │
        ├─ useServiceOrg() → MainLayout 组织 Tag
        │                  → filterAvailableMenuTree(…, serviceOrg) 组织过滤
        └─ useOrgEpoch()   → PermissionProvider 重拉 /menus + /user/menus
                           → MainLayout 清空页签实例、重置回工作台
```

两个写入入口的分工：

- `captureServiceOrg(headers)`：每个 API 响应都调用，**只更新 orgId，不动 epoch**。
  组织是服务器属性，正常请求不该触发界面刷新；值没变就不通知。
- `notifyOrgSwitched(orgId)`：只在**显式切换**时调用（app 事件监听），orgId 更新且
  epoch+1，触发菜单重拉与页签重置。

## 四、web 端：nginx 配置

每台组织的部署写自己的 OrgID：

```nginx
# 越南部署
location /v1/boda/ {
    add_header Service-Org "0001E610000000KWHO9D" always;
    proxy_pass http://127.0.0.1:8080;
}
```

- `always` 必须带：4xx/5xx 响应也加头。前端在判定请求成败**之前**捕获
  （`src/api/request.ts:170`），登录失败等场景同样能确定组织。
- 头名大小写不敏感（fetch `Headers` 规范化），nginx 写 `Service-Org` 即可。
- 组织 ID 常量见 `src/store/orgs.ts` 的 `ORGS`：义乌工厂 `0001E610000000KO20VW`、
  越南工厂 `0001E610000000KWHO9D`、供应链、顺杰、硕杰。

## 五、前端代码路径

### 5.1 `src/utils/service-org.ts` — 运行时状态（无 React）

| 导出 | 作用 |
|---|---|
| `ORG_CHANGED_EVENT` | `'boda-org-changed'`，Go 侧 Eval dispatch 的事件名 |
| `captureServiceOrg(headers)` | 从响应头读 `service-org`，更新 orgId |
| `notifyOrgSwitched(orgId)` | 显式切换：orgId 更新、epoch+1 |
| `getServiceOrg()` / `getServiceOrgSnapshot()` / `subscribeServiceOrg()` | 非 React 读取与订阅 |

模块加载即注册 `window` 事件监听，任何一次切换都不会因「监听还没挂上」而丢失。
刻意不 import api / store，请求层才能安全 import 它而不循环依赖。

### 5.2 `src/store/service-org.ts` — React 绑定

`useServiceOrg()`（orgId）、`useOrgEpoch()`（epoch），`useSyncExternalStore` 接入。
只导出 hook，不导出组件，Fast Refresh 边界干净。

### 5.3 `src/services/permission.ts` — 组织过滤纯函数

```ts
// :33  与 C# Main.cs:642 的 UseOrgs.Contains(OrgID) 同语义
export function menuMatchesOrg(node, orgId) {
  if (isDebugEnv) return true;      // 调试豁免
  if (!orgId) return true;          // 没配头 fail-open
  if (!node.UseOrgs) return true;   // 没配 UseOrgs = 所有组织可见
  return node.UseOrgs.includes(orgId);
}
```

`filterAvailableMenuTree(nodes, hasPage, orgId)`（`:51`）在原有「Release + 页面完成度」
过滤上叠加组织过滤，由 `MainLayout.tsx:182-185` 调用。
`UseOrgs` 字段定义在 `src/api/modules/power.ts:18`（`DesktopMenu.UseOrgs: string`），
**值来自后端菜单数据**，多个组织 ID 直接拼接，子串匹配；组织 ID 是定长 GUID，不会误命中。

### 5.4 `src/store/permission.tsx` — 切换后重拉

`useOrgEpoch()` 进 `useEffect` 依赖：epoch 变化即重拉 `/menus` 与 `/user/menus`
（菜单与权限是按服务器组织下发的）。其余权限逻辑见关联文档。

### 5.5 `src/layouts/MainLayout.tsx` — Tag 与页签重置

- `:166-167` 取 `serviceOrg` / `orgEpoch`；
- `:192-199` epoch 变化时：`tabInstances.current.clear()`、页签重置为 `[HOME_TAB]`
  （工作台）、`setOpenKeys([])`。**刻意行为**：开着的页签都按旧组织取数，留在原页会
  显示错组织的数据；
- `:594-601` 组织 Tag：`serviceOrg` 非空才渲染，用户信息 Dropdown 左侧，
  `<Tag icon={<ClusterOutlined/>} color="blue">{ORG_NAME(serviceOrg)}</Tag>`。
  未知组织显示原始 ID（`ORG_NAME` 的兜底），没配头不显示。

### 5.6 `src/store/orgs.ts` — 名称映射

`ORGS`（ID→名称）、`ORG_NAME`（兜底原始 ID）、`ORG_ID`、`ORG_SELECT_OPTIONS`。
**只服务于显示**；app 下拉的组织名称用服务端 `/login/userOrgs` 返回的 `OrgName`，
不查这张表。

## 六、app 端：动态切换组织（无需重启）

### 6.1 架构前提

页面以 `mygo://localhost` 提供，所有 API 经应用内代理 `http://127.0.0.1:<随机端口>`
（`app/proxy.go`）转发；注入页面的 `apiBaseUrl` 是**代理地址**，不是真实服务器。
因此「换服务器」= 换代理上游，注入值不变 → 无需重启、无需重新注入。
ws（Agent）与语音（ASR）地址页面直连，**切换组织绝不改动**。

### 6.2 `app/proxy.go`

| 位置 | 作用 |
|---|---|
| `:49` `apiTarget atomic.Pointer[url.URL]` | API 上游 origin，原子替换 |
| `:80` `retargetAPI(apiBaseURL)` | 运行时换上游，只动 API |
| `:91` `currentAPIOrigin()` | 当前上游（拉组织列表用） |
| `:191` `Access-Control-Expose-Headers: Service-Org` | 跨域（mygo:// → 127.0.0.1）下浏览器能读到该头，**漏了它 app 端 Tag 不显示** |

### 6.3 `app/org.go` — 对应 C# 主窗口底部组织下拉

| 函数 | C# 对应 | 语义 |
|---|---|---|
| `Org` 结构 | `Models/Config.cs` 的 `Org` | `OrgID/OrgName/ApiHost/ApiDomain`；`ApiHost` 是纯 origin，路径前缀 `/v1/boda` 另算 |
| `fetchOrgs(token, basePath)` | `LoadOrgs` | `GET <origin><basePath>/login/userOrgs?userID=`（userID 留空，服务端按 token 识别）；10s 超时；忽略空 OrgID；同时返回响应头的 `Service-Org` |
| `initialOrgName(orgs, serverOrg, savedOrg)` | `LoadOrgs` 选中逻辑 | 优先服务器自报 → 配置记住的 → 第一个 |
| `switchOrg(org, basePath, page)` | `OrgEdit_EditValueChanged` | 写盘（仅 `APIBaseURL=ApiHost+basePath` 与 `OrgID`）→ `retargetAPI` → 通知页面 |
| `notifyPageOrgChanged` | 通知已打开页面 | `page.Eval` dispatch `boda-org-changed`，orgID 转义防截断 |

`ApiHost` 为空时留在当前服务器（只切换组织身份），与 C# 一致。

### 6.4 `app/settings_window.go` — 设置窗口组织区

- 打开窗口即 `loadOrgs()`（`:91`、`:253`）：token 从主窗口页面
  `localStorage.getItem('boda_token')` 读（与前端同一份）；未登录给提示，不切换；
- 组织下拉选中即 `switchSelectedOrg()`（`:137`、`:318`）：goroutine 里切换，
  失败回滚下拉选中项，成功回写地址输入框与 `appSettings`；
- 「刷新」按钮重拉组织列表（`:140`）；加载中/切换中下拉与按钮禁用；
- `save()`（`:209`）携带 `OrgID` 一起写盘。

### 6.5 `app/settings.go` — 持久化

`Settings.OrgID`（json `orgId`）**仅用于设置窗口回显选中项**；页面侧的组织始终以
`Service-Org` 响应头 / 切换事件为准。切换只改 `APIBaseURL` 与 `OrgID`，
`AgentWSURL` / `ASRURL` 沿用盘上原值。

## 七、常见调整场景

### 7.1 某个菜单只对越南可见（或改组织归属）

改**后端菜单数据**的 `UseOrgs`：填越南 OrgID（多组织就拼接多个 ID）。
前端零改动、不用重新编译。本地想预览：mock 的
`src/api/mock/data/desktopMenu.json` 里给节点加 `UseOrgs`，再以 release 环境跑
（见 7.6）。

### 7.2 新增一个组织

1. 该组织部署的 nginx 加 `Service-Org` 头（web 生效）；
2. `src/store/orgs.ts` 的 `ORGS` 加 ID→名称（Tag 显示名称，不加则显示原始 ID）；
3. 后端 `/login/userOrgs` 返回该组织（带 `ApiHost`），app 下拉自动出现，无需改 Go。

### 7.3 改 Tag 样式 / 位置

`src/layouts/MainLayout.tsx:594-601`。显示条件只有一个：`serviceOrg` 非空。

### 7.4 页面内响应组织变化

`const org = useServiceOrg()` 取当前组织；`const epoch = useOrgEpoch()` 做
「组织变了就重取数」的 effect 依赖；非 React 场景监听 `window` 的
`boda-org-changed`（`detail.orgId`）。

### 7.5 改组织列表接口 / 字段

`app/org.go` 的 `Org` 结构与 `fetchOrgs`。注意保持「忽略空 OrgID」「ApiHost 为空
留在当前服务器」两条 C# 语义，除非刻意要改。

### 7.6 本地想看 Tag / 组织过滤效果

mock 在 fetch 之前就返回（`src/api/request.ts` 的 mocked 分支），**不经过
`captureServiceOrg`**，所以默认 dev 看不到 Tag。两种办法：

1. 对着配了头的 nginx 跑 release 环境：
   `VITE_APP_ENV=release VITE_USE_MOCK=false npm run dev`；
2. 控制台手动 dispatch（纯 UI 验证）：
   `window.dispatchEvent(new CustomEvent('boda-org-changed', {detail: {orgId: '0001E610000000KWHO9D'}}))`
   → Tag 变越南工厂；release 环境下菜单随即按 mock 的 `UseOrgs` 过滤。
   debug 环境下 Tag 会显示但菜单过滤豁免。

### 7.7 改切换后的页签行为

`MainLayout.tsx:192-199`。当前是「全部重置回工作台」；若要保留页签，需自行保证
页内数据按新组织重取（每个页面都得响应 epoch），不建议。

## 八、注意事项与已知坑

1. **组织过滤是 UI 层便利，不是安全边界**。后端必须独立校验组织归属，与权限模块
   同一原则（见关联文档第八节）。
2. **`always` 漏配**：错误响应没头，登录失败等场景组织识别不到。
3. **app 代理漏配 `Expose-Headers`**：跨域下 `Headers.get('service-org')` 读不到，
   app 端 Tag 与过滤静默失效（fail-open），排障先查这里。
4. **capture 不动 epoch**：若发现「切了组织菜单没重拉」，检查走的是不是
   `notifyOrgSwitched` / 事件路径，而不是指望响应头触发刷新。
5. **`UseOrgs` 是子串匹配**：配置时直接拼接定长 ID 即可；不要填名称、不要加分隔符
   以外的花样。空串 = 所有组织可见。
6. **settings.json 的 `orgId` 不是权威**：它只回显下拉。手改它不会改变页面组织，
   页面组织以头 / 事件为准。
7. **页签重置是刻意行为**（见 5.5），不是 bug。
8. **debug 豁免组织过滤**：本地「什么菜单都有」不代表 release 也有，验收要用
   release 环境 + 配头服务器。
9. **设置窗口未登录**（无 `boda_token`）只提示不切换；组织列表请求带 `token` 头，
   与前端请求层同一份 token。
10. **C# 对照**：`Main.cs` `OrgEdit_EditValueChanged` ↔ `switchOrg`；`LoadOrgs` ↔
    `fetchOrgs`；`Main.cs:642` `UseOrgs.Contains(OrgID)` ↔ `menuMatchesOrg`；
    `BasePath="/v1/boda"` 与 `ApiHost` 分离 ↔ `switchOrg(org, basePath, …)`。
