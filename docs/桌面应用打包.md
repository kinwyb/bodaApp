# 桌面应用（生成 app / 打包）

> 基准版本：`main` @ `4e87225`（2026-10-16）
> 打包代码：`app/`（Go + MyGo，5 个源文件）
> 前端：项目根的 `src/`，构建产物 `dist/`

---

## 一、一句话结论

前端是普通 web 应用，**桌面壳只负责开一个系统 WebView 窗口并加载页面**，不含任何业务逻辑：

```bash
npm run app:dev      # 开发：热更新，窗口指向 Vite dev server
npm run app:build    # 打包：先 npm run build，再把 dist/ 内嵌进单文件可执行程序
```

产物在 `app/dist/<os>-<arch>/`，macOS 下是 `bodaWay.app` + `bodaWay <版本>.dmg`。

---

## 二、结构：为什么配置在 `app/` 而前端在根目录

```
bodaWay/
├── src/  dist/  package.json      # web 前端（常规 Vite 项目）
├── app/                           # MyGo 的项目根，打包相关全在这里
│   ├── main.go                    # 应用入口：开窗 + 生命周期
│   ├── mygo.config.ts             # 应用名 / 标识 / 版本 / 开发与构建命令
│   ├── go.mod                     # module …/app，依赖 mygo v0.3.5
│   ├── mygo.ts                    # CLI 生成的 TS 客户端（gitignore，本项目未使用）
│   ├── dist/                      # 打包产物（gitignore）
│   └── .mygo/dev/                 # 开发态应用（gitignore）
└── .env.development / .env.production
```

`mygo.config.ts` **必须在项目根**，所以把项目根设在 `app/`，配置里用 `..` 指回前端：

```ts
export default defineConfig({
  name: "bodaWay",
  identifier: "com.bodaway.app",
  version: pkg.version,            // 唯一来源：根 package.json 的 version
  devUrl: "http://localhost:5173",
  devCommand: "npm --prefix .. run dev",
  buildCommand: "npm --prefix .. run build",
  frontendDist: "../dist",
});
```

`main.go` 只有约 60 行：`WhenReady` 里开 1280×800 的窗口（`StateKey: "main"` 记住位置和尺寸），
`OnWindowAllClosed` / `OnActivate` 按 macOS 习惯处理（关窗口不退进程，点 Dock 图标重开窗）。
窗口 `URL` 写不带 scheme 的 `/`：dev 时解析到 `devUrl`，打包后解析到 `mygo://localhost/`。

**前端与桌面壳完全解耦**：`src/` 里没有任何 `mygo` 引用，前端可以单独 `npm run dev` 在浏览器里跑。

## 三、环境要求

| 项 | 要求 | 本机 |
| --- | --- | --- |
| Go | 1.27+（`app/go.mod` 声明 `go 1.27.1`，版本低时 `GOTOOLCHAIN=auto` 会自动拉工具链） | 1.27.3 ✅ |
| Node | 22.6+（CLI 用它评估 `mygo.config.ts`；有 Bun 也可以） | v22.22.2 ✅ |
| CLI | `mygo-cli@0.3.5`（devDependency，用 `npx mygo` 或 npm 脚本调用） | ✅ |
| 系统 | macOS 12+ / Windows 10+（需 WebView2）/ Linux（GTK3 + WebKitGTK 4.1） | macOS 27.2 ✅ |

自检：`npx mygo doctor`。可选组件缺失只影响某些能力，不影响本机打包：

| 缺失项 | 影响 |
| --- | --- |
| `codesign` / Developer ID | **只能 ad hoc 签名，产物仅本机能跑**（见第七节） |
| `makensis` | 不能在 macOS 上生成 Windows 安装器 |
| `osslsign` | 不能在 macOS 上签 Windows 程序 |
| `bun` | 无影响（本项目用 Node） |

> 在受限环境（沙箱 / 冻结的 CI 镜像）里跑 `go` 会被拦在 `~/Developer/go/pkg/mod`（工作区外的模块缓存）。
> 把缓存指到可写位置即可：`export GOMODCACHE=/tmp/boda-go-mod GOCACHE=/tmp/boda-go-cache`。
> 正常终端里不需要。

## 四、开发（`npm run app:dev`）

```bash
npm run app:dev      # = mygo dev app
```

它按顺序做四件事：生成 TS 客户端 → 跑 `devCommand`（即 `npm run dev`）→ 等 `localhost:5173` 就绪 →
构建并启动开发态应用。

- **不用自己先开 `npm run dev`**，否则 5173 被占用，`mygo dev` 拉起的那个会失败。已在跑时用
  `npx mygo dev app -skip-dev-command`。
- 改 `app/` 下的 Go / 配置会**自动重建重启**（先退旧进程）；前端改动走 Vite 热更新，不重启。编译失败时保留正在运行的旧版本。
- 终端按键：`r` 重建、`c` 清屏、`q` 退出、`h` 帮助。
- 开发态应用名是 **`bodaWay Dev`**、identifier 是 `com.bodaway.app.dev`，数据、偏好、单实例锁与正式应用**隔离**。
  比打包后的 app 更"干净"是正常的，别拿开发态去验证登录态持久化。

## 五、打包（`npm run app:build`）

```bash
npm run app:build                       # = mygo build app，产物在本机平台
npx mygo build -skip-build-command app  # 前端 dist/ 已经是最新时，跳过 npm run build
npx mygo build -debug app               # 保留 web inspector，排查线上白屏很有用
npx mygo build -skip-dmg app            # 只要 .app，不要磁盘映像
npx mygo build -o /tmp/out app          # 换输出目录
```

⚠️ **flag 必须写在目录前面**（`mygo build [flags] [dir]`）。写成 `mygo build app -skip-dmg` 时，
Go 的 flag 解析在遇到第一个位置参数 `app` 就停了，后面的 flag **被静默忽略** —— 看起来跑了、但该跳的没跳。

流程：跑 `buildCommand`（= `npm run build`，即 `tsc -b && vite build`）→ 把 `dist/` **内嵌进可执行文件** →
按平台打包到 `app/dist/<os>-<arch>/`。壳本身编译 + 签名只要 1~2 秒，时间几乎全花在前端构建上。

macOS 产物（约 13.7 MB，前端全在内）：

```
app/dist/darwin-arm64/
├── bodaWay.app                 # 可直接双击运行（已 ad hoc 签名）
└── bodaWay 0.0.0.dmg           # 名字里的版本号来自 package.json
```

⚠️ **dmg 需要挂载磁盘映像**（`hdiutil` 会临时挂到 `/Volumes/bodaWay`）。在没有挂载权限的环境里
（沙箱、部分 CI）这一步会失败，前面已经编好的 `.app` 不受影响 —— 加 `-skip-dmg` 跳过即可。
本机终端直接跑没有这个限制。

跨平台：

```bash
npx mygo build -platform darwin/universal,windows/amd64,linux/amd64 app
```

| 约束 | 说明 |
| --- | --- |
| macOS 签名 / dmg | **只能在 macOS 上做**（本机就是） |
| Windows 安装器 | 需要 NSIS（`brew install makensis`），否则只有裸 exe |
| Linux 产物 | 建议在 Linux 上打（`.deb` / `.desktop` 依赖那套工具） |
| cgo | 默认 `CGO_ENABLED=0`，纯 Go 交叉编译没问题；引入需要 cgo 的依赖时要显式设 `1` |

⚠️ **`app:build` 会跑 `tsc -b`**，类型错误直接中断打包（这是好事）。它的 `prebuild` 还会跑
`menu:descriptions`，把 `bridged.ts` 的 `guide.summary` 同步进同目录的 `description.md` ——
一致时不动，不一致时**会改写文件**。所以打包后先看一眼 `git status`，别把生成物当成自己的改动提交。

## 六、服务器地址：web 走反代，app 走应用内配置

同一份前端有两种跑法，地址来源完全不同 —— 这两件事不要混：

| 跑法 | 页面 origin | 地址怎么来 |
| --- | --- | --- |
| 浏览器访问服务器上的前端 | 服务器域名 | **相对路径 `/v1/boda` + nginx 反向代理**，前端不关心具体地址 |
| 桌面 app（内嵌前端） | `mygo://localhost` | **必须是绝对地址**，由用户在应用内设置 |

桌面端之所以特殊：前端被打包进可执行文件，页面没有「同源的反向代理」可用，`vite.config.ts` 的 proxy
也全部失效，相对路径会被解析到应用自身的内嵌资源上（404）。

### 应用内设置：`bodaWay → 设置服务器地址…`（`⌘,`）

Windows / Linux 在「文件」菜单里。窗口是 **MyGo 原生 UI**（Go 画的，不是网页），
因为这个窗口要在「地址配错、页面连不上后端」时照样能打开 —— 做成网页就得先加载前端、先拿地址，
正好卡在它要解决的问题上。窗口无边框、固定尺寸：没有缩放 / 最小化 / 关闭按钮，关掉它用底部的「关闭」，
拖动靠顶部自绘的标题区（`Element.DragWindow`）。

三个输入框，留空表示用内置默认值：

| 输入框 | 对应变量 | 说明 |
| --- | --- | --- |
| 后端接口地址 | `VITE_API_BASE_URL` | 要带 `/v1/boda` 前缀 |
| Agent 服务地址 | `VITE_AGENT_WS_URL` | `ws://` / `wss://` |
| 语音识别地址 | `VITE_ASR_URL` | 根地址即可，前端自己补 `/asr` |

- 保存写 `~/Library/Application Support/bodaWay/settings.json`（Windows 是 `%APPDATA%\bodaWay\`）。
- **保存后需重启生效**，窗口里会给一个「立即重启」按钮。之所以不做热重载：地址在页面脚本之前就要注入，
  热改等于把整页重新加载一遍，还不如重启干净。
- 「清空」只清输入框，还要点保存才写盘 —— 免得误点一下就把在用的地址删了。
- 校验在保存前做：接口/语音要 `http(s)://`，Agent 要 `ws(s)://`，且必须带主机名。填错的地址会带进下次启动，
  那时候前端直接请求失败、连页面都进不来，所以只能在这里拦住。

### 优先级

```
app 内配置（settings.json）  >  构建期 .env  >  代码里的兜底值
        ↓ 都没配时
      相对路径 /v1/boda（仅 web 部署成立）
```

技术上是 Go 侧把配置注入到页面的 `window.__BODA_SETTINGS__`（`PageOptions.PreloadScript`，在页面脚本之前执行），
前端统一在 `src/utils/runtime-config.ts` 里合并，**其余代码不再直接读 `import.meta.env` 的地址变量**。

### 构建期默认值（`.env.production`）

这几项仍然有意义：它们是 app 的**出厂默认**，也是 web 部署时的取值。app 里配过就以配置为准。

| 变量 | 开发（相对，走 proxy） | 打包（绝对） | 现状 |
| --- | --- | --- | --- |
| `VITE_API_BASE_URL` | `/v1/boda` | `http://192.168.9.9:82/v1/boda` | ✅ `.env.production` 已配 |
| `VITE_AGENT_WS_URL` | `ws://127.0.0.1:8765/ws` | `ws://<host>:<port>/ws` | ❌ 未配（可在 app 内补） |
| `VITE_AGENT_FILES_URL` | `/ws/files` | 一般不用配，由 WS 地址推导出 `http(s)://<host>/ws/files` | 自动 |
| `VITE_ASR_URL` | 不用配，`/asr` 走 proxy | `http://192.168.9.16:9383` | ❌ 未配（可在 app 内补） |

构建期没配的后果：**Agent 走本地演示脚本**（界面上不报错，但内容是假的）、**语音输入请求
`mygo://localhost/asr` 拿到 404**（麦克风点了没反应）。装上 app 后在设置窗口里补齐即可，不必重新打包。

⚠️ 跨域：从 `mygo://localhost` 请求后端属**跨域**，后端 nginx 必须放行这个 origin
（`Access-Control-Allow-Origin`），并允许 `Authorization` 头（否则先撞 OPTIONS 预检）。
这条在本地调试时不会暴露，只有打包后才出现 —— 换服务器地址时同样要确认。

## 七、签名与分发

当前 `mygo.config.ts` **没有配 `macos.signingIdentity`**，产物是 ad hoc 签名：

- 本机能双击运行；
- 拷到别的 Mac 上会被 Gatekeeper 拦（"无法打开，因为无法验证开发者"）。

要正式分发，需要 Apple Developer ID：

```ts
macos: {
  signingIdentity: "Developer ID Application: 公司名 (TEAMID)",
  notarize: { appleId: "…", teamId: "…", password: "…" },  // 或用 keychain profile
}
```

公证前先 `xcrun notarytool store-credentials`。这也是 `mygo doctor` 里 `codesign ✗` 的含义 ——
**不是没装 codesign，是没有可用的 Developer ID 证书**。

内部试用可以绕过（不是解决方案）：用户右键 →「打开」，或 `xattr -dr com.apple.quarantine bodaWay.app`。

Windows 侧用 `windows.certificate`（密码走 `MYGO_WINDOWS_CERTIFICATE_PASSWORD`）或 `windows.signCommand`。

## 九、行为差异与排错

打包态与浏览器里的差异（都是 origin 变了导致的，不是 bug）：

| 现象 | 原因 |
| --- | --- |
| 页签宽度、折叠状态、登录态全丢 | `localStorage` 按 origin 隔离，`localhost:5173` 与 `mygo://localhost` 不互通 |
| 接口全 404 | `VITE_API_BASE_URL` 还是相对路径，或没重新构建 |
| 接口 CORS 报错 | 后端没放行 `mygo://localhost` |
| Agent 一直回演示内容 | app 内没配 Agent 地址，构建期也没配（`VITE_AGENT_WS_URL` 为空） |
| 语音输入没反应 | 同上：`ASR` 地址缺失，请求打到了内嵌资源 |
| 改完地址没生效 | 设置窗口保存后需要重启（窗口里有「立即重启」） |
| 白屏、控制台看不到错 | 用 `npx mygo build app -debug` 重打，右键「检查元素」看 console |
| 窗口标题变了 | 页面 `usePageTitle` 会写 `document.title`，MyGo 窗口标题跟随它 —— 这是预期行为 |

SPA 路由不用配：`mygo://localhost/` 下不带扩展名且匹配不到文件的路径会**自动回退 `index.html`**，
react-router 的 history 模式开箱即用。

## 十、以后要加桌面能力

目前壳里没有任何 `mygo.Bind`，前端也不需要。真要加（读本地文件、系统托盘、原生对话框）时的路径：

1. 在 `app/main.go` 里 `mygo.Bind(&Service{})`（必须在 `App.Run` 之前），或 `mygo.NewEvent[T]("名字")` 声明事件；
2. `npm run app:dev` 会自动生成 `app/mygo.ts`（带类型的客户端，勿手改，已 gitignore）；
3. 前端 import 它 —— ⚠️ 注意 `tsconfig.app.json` 的 `include` 只有 `src`，跨目录引用会报"不在 project 内"，
   需要届时把 `app/mygo.ts` 纳入 include 或加路径映射；
4. **不要**再引入 Electron 式字符串通道，也不要在 `src/` 里做运行环境探测来决定"有没有桌面能力" ——
   保持前端可在浏览器里独立运行。

另外记住 `mygo generate` 会**以 `MYGO_GENERATE` 环境变量启动应用**（`App.Run` 写完客户端就返回，不开窗），
所以 `main` 里到 `App.Run` 之间的代码在生成时也会执行一遍 —— 迁移、建表这类副作用必须放进 `WhenReady`。
